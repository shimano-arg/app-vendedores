# Audit APP VENDEDORES — 2026-10-13

6 agentes paralelos (security, architecture, performance, accessibility, silent-failures, code-quality). **Total findings: 122 (24 CRITICAL / 42 IMPORTANT / 56 MINOR)**. Reportes detallados en `docs/AUDIT_2026-10-13/*.md`.

## Executive summary

El riesgo #1 ahora mismo es **financiero/split-brain SAP↔Firestore**: `sq-cancel-core.js` tiene dos silent failures encadenadas (S1 + S2) que, apenas se arregle el primero, abren una condición tipo FATECHI que marcará líneas `cancelled` en Firestore mientras la SQ sigue viva en SAP. En paralelo, un vendedor puede inflar su propia comisión escribiendo `paidStatus`/`paidAmount` en sus propios pedidos (C2-sec) y cualquier VDE puede borrar la waitlist de otro VDE (C1-sec). El **próximo hito más valioso** es cerrar los dos cross-stream disparadores de incidentes (SQ cancel + Planner duplicate email) y luego formalizar la **state machine de pedidos** (A2 arch): hoy está implícita en 3+ sitios, es la raíz compartida de FATECHI/LAMORA/username/pending-fantasma.

## Findings por área (links a subfiles)

### Architecture — 14 findings (3 hot / 6 medium / 5 low)
Hot zones: (A1) `index.html` inline script 26,200 LOC con pedido domain inside, (A2) state machine implícita duplicada en 3+ sitios (raíz FATECHI/LAMORA class), (A3) shell bundle 2.5 MB bloquea first paint. Medium: solo 5/30 listeners usan `ensureListenerWithFallback`, 3 CF handlers violan CLAUDE.md #7, dual-impl `computeColumn` sin test parity. Detalle: `docs/AUDIT_2026-10-13/architecture.md`.

### Performance — 20 findings (3 high-ROI / 10 medium / 7 low)
Baseline terrible: LCP 28.6s / FCP 14.5s / Lighthouse 26 en Slow 4G. Shell 2.47 MB (64% sobre techo CLAUDE.md #16). 10 CFs scan unbounded `pedidos` → ~35 GB/mes Firestore reads. Top wins: P1 split shell (-371 KB), P2 extraer `POINTS` + `PRODUCTS` inlineados (-220 KB), P3 `operations_log limit(2000)→200` (-90% bandwidth). Detalle: `docs/AUDIT_2026-10-13/performance.md`.

### Accessibility — 20 findings (6 CRIT / 8 IMP / 6 MIN)

Positivo: dark mode (v745) sólido, mobile bottom-nav bien ARIA, safe-area insets honored. Detalle: `docs/AUDIT_2026-10-13/accessibility.md`.

## Overlaps detectados (findings en 2+ reportes = señal fuerte)

1. **Shell bundle gigante** → Arch A1 (26,200 LOC inline) + Arch A3 (2.5 MB shell) + Perf P1 (shell split) + Perf P2 (POINTS/PRODUCTS inline). Cuatro ángulos del mismo problema: el shell no se pudo adelgazar porque el pedido lifecycle vive inline. **Un solo refactor (extraer pedido-lifecycle) desbloquea los 4**.
2. **State machine implícita** → Arch A2 (3+ sitios con reglas duplicadas) + Code Q2 (`buildQuotationPayload` CF+client sin parity) + Code Q3 (`planner-compute-column` byte-identical dual file sin test) + Silent S3 (planner email duplicado por `sentAt` no persistido antes). Mismo síntoma de "no hay single source of truth del stage".
3. **FATECHI class recurrente** → Silent S1+S2 (sq-cancel split-brain) + Silent I1 (markLinesCancelled después de SAP cancel) + Silent I3 (`getUserVendor` fail-open abre spoof) + Code Q2 (payload CF↔client drift). Patrón: pre-check cliente OK, flow server-side sin la misma protección.
4. **Audit log holes** → Security M3 (operations_log mutable via Admin SDK) + Silent I6 (`logOp` empty catch) + Silent I7 (`onPedidoCreatedCleanupWaitlist` fail-close silencioso). Audit trail no es confiable para forensics.
5. **`sl.username || sl.userName` fallback 14 veces** → Security positive-obs (patrón aplicado) + Code Q6 (repetido 14x sin helper) + CLAUDE.md #24 (precedente v918→v999 bug). Cualquier CF nueva sin fallback repite el bug.
6. **Modal infrastructure débil** → A11y A2 (zero `role="dialog"`) + A11y A5 (3/50 Escape) + A11y A19 (focus no restored) + Code Q8 (asig modal handlers reset). Un solo `_openModal(id)` helper cierra 4 findings.

## Riesgos cruzados (combinaciones peligrosas)

- **C2 security (commission inflation) + S4 silent (fire-and-forget enrichment) + Audit log holes (M3/I6/I7)** = pérdida financiera **no detectable**. VDE escribe `paidStatus='paid'` directo + enrichment lines fallan silenciosos + logOp swallows → ninguna huella. Cierra C2 y endurece audit log antes que todo lo demás.
- **S1+S2 sq-cancel + I2 security (`interno` list all pedidos)** = un interno con token comprometido puede trigger-ear re-sincs que gatillen el split-brain a escala. Cierra S1+S2 juntas, nunca separadas.
- **A1 arch (monolito pedido inline) + L3 arch (0 tests inline) + Code god-functions (`doConfirmPedido` 481 LOC)** = cualquier cambio al confirm flow es ciego. Extraer `doConfirmPedido` → `src/pure/` + tests DEBE preceder a refactors arquitectónicos grandes.
- **C4 security (password gate débil + hashes readables) + I6 security (`get` allowed_emails leak)** = admin comprometido lee TODO roles + password hashes + emails whitelist + puede impersonar cualquier usuario sin disparar lockout (M6). Password gate overhaul debe hacerse completo, no por partes.
- **S3 silent (Planner duplicate email) + Perf P14 (CF cold start sapProxy)** = en picos post-cold-start, el send tarda 3-5s y aumenta la probabilidad de retry → emails duplicados escalan.
- **A11y A1 viewport zoom + A11y A6 focus-ring invisible light-mode** = VDE con presbicia outdoor NO puede navegar la app teclado-only. Dos fixes de 1 línea cada uno.
